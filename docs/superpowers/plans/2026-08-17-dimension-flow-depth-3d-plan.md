## WP1 · 场流光 v3（2D macOS 抠图效果重做）

**诊断（回答"opus 的问题还是实现的问题"）：是实现方式的问题。**
v1/v2 用"质心极角 θ"当作沿轮廓的行进坐标——这只对**星凸形状**成立。树、风车、字母这类凹形轮廓，同一极角会穿过轮廓多次：光不是"沿着边缘走"，而是"按角度扇形扫过"，凹陷处跳变、分支处撕裂——这就是效果廉价感的几何根源，换任何模型都救不了这个参数化。

**v3-GPU 实况（2026-08-17 user 拍板 shader 路线，Phase A-C 已落）：**
- Phase A 审计：359 件全库 AST 可编译性——**342 件 (95%) ≥1 层可流光**，层级 92%。缺口全部是无-AST 裸闭包层 / 伪 3D 原语 / revolve-extrude-twist（合计 18 用）。
- Phase B 发射器：`src/sdf/sdf2.compile.js`（语句式，polygon/circular_array 按字面量展开，ES 1.00 安全）。三重验证：glslang 8760/8760 · 真 Chrome GPU 编译 8760/8760 · 32×32 距离场数值等价 8758/8760 在 3e-3 内（余 2 例 float32 平滑并集累积 3.9e-3，不可见）。顺手修 sd2Ellipse float32 数值悬崖（acos/sqrt 越域 → NaN，加 CPU 同款钳位，revolve/extrude 同受益）。
- Phase C demo：`examples/genlab/flow-gpu.html?piece=` — weave 底图 + WebGL overlay，主角层页内编译，**切向噪声平流** `glow = exp(−|d|k)·fbm(p·s − tangent·t)`——光贴全轮廓爬行，凹形天然安全（树/风车免拓扑追踪）。参数 `?speed=&band=&freq=` 可调。
- 后续开口：白圆头彗星（CPU marching squares 折线 → uniform 光头位置）可叠在平流底上；DIMENSION 岛内落地待 user 过目 demo 后做。

**v3 方案（原 CPU 追踪案，彗星头会回用其折线核）：真·轮廓追踪。**
1. 在场缓存上跑 **marching squares** 提取 SDF=0 等值线 → 闭合折线（一物多环时取最长主环；洞环丢弃）；
2. **弧长参数化**：折线累计弧长归一化，光头位置 = `s(t) = (t/lap) mod 1`，恒定线速度（凹凸处不再忽快忽慢）；
3. 渲染改用 **canvas 直接画光斑**沿折线撒点（光头白色圆 + 身后按弧长高斯衰减的色斑序列 + shadowBlur 辉光），废除逐像素帧循环——更亮、更顺滑、60fps 无压力；
4. 蜿蜒绸带感保留：撒点沿轮廓法向做小幅正弦摆动（现有 weaveAmp 语义平移过来）；
5. 选角逻辑（覆盖率 + 贴边率 + 串联编排）v2 已验证，原样保留。

验收：树形凹轮廓（birdcage/windmill）+ 大主体（dust-storm）+ 小主体（teapot）三类，光贴边匀速绕行无跳变、无撕裂。

## WP2 · 3D 景深（Pasma depth-cues 落地）

文章线索清单中适配点彩光追管线的四条，全部由"hit 距离 t"驱动（**前置改造：probe 返回值增加 `dist` 字段**，现只有 intensity/region）：

| Cue | 点彩落地方式 | 备注 |
|---|---|---|
| **大气透视** | 远处笔触密度衰减 + 颜色向天色/浅支渐混：`fog = 1 − exp(−dist·k)` 进密度公式与色窗 | 主力 cue，最便宜最有效 |
| **焦点模糊 DoF** | 离焦量 `|dist − focal|` 调制**笔刷尺寸与透明度**——点彩的"模糊"就是更大更淡的笔触，天然媲美高斯模糊且血统纯正 | focal 平面位置做 hash trait |
| **纹理梯度** | cell 细分度随 dist 变粗（近处 4px 细胞、远处 8-16px） | 与 DoF 共用调制通道 |
| 阴影/遮挡/透视 | 光追已天然具备 | 无需动 |

Trait 化：`fogK`（雾浓度）、`focal`（焦平面）入 hash 参数；概率表补一行"深景 vs 浅景"档。
验收：胶囊林（多深度物体）before/after——远胶囊应退成薄雾轮廓、焦外应软化。

## WP3 · 3D 抠图光流转

**统一洞察：3D 的"SDF=0 可见轮廓"在屏幕空间就是 hit-mask 的边缘。**
1. 3D 渲染 probe 阶段顺手写一张低分辨率 **object mask**（region=='object' 即 1）；
2. 对 mask 跑 **与 WP1 完全相同**的 marching squares + 弧长流光——WP1 的追踪/编排/渲染代码整体复用，输入从 2D SDF 场换成 mask；
3. 3D 特有深化（可选二期）：光斑亮度按该处**法线与视线掠射角**调制（`1−|n·v|`）——光绕过球体边缘时呈真实 rim-light 的明暗呼吸；probe 已返回 normal，零额外成本。

依赖：WP1 先行（共享核心）。验收：茶壶（壶嘴壶柄的凹轮廓）+ 球（简单凸）双测。

## 风险与开口

- marching squares 在细分支（1-2 像素宽的树枝）上可能断环 → 场缓存分辨率提到 480 或对断环做最近端点缝合；
- SceneData 解释器的原语覆盖面以选片实测为准（火箭只用 box/cylinder/sphere/union，预计 ~8 原语 + 3 变换 + 2 布尔即覆盖 80% 语料）；
- Mandelbulb CPU 单帧成本高 → 先测 640px 渲染时长，超 90s 则降分辨率或降档为超稀有（低出现率摊薄等待）。
